# 详细设计文档

## 选择输出

读取内置 `assets/template.xml`，不依赖原飞书模板。用户给飞书链接时选择飞书，指定 Word／docx 时选择 Word，同时指定则两种都交付。未指定时简短询问输出形式，并继续不依赖答案的代码调研。Word 用户无需连接飞书。

## 调研与写作

1. 读取适用 AGENTS.md，检查实际入口、配置、加载、调度、状态、验证和汇总。先发现事实再询问，只有文档可访问时声明未做代码核对。
2. 背景先明确上层产品、入口、执行引擎、适配落点与仓库职责；核对 Python API、HTTP、CLI、子进程等实际调用方式。
3. 外部协议、模型和基准查官方一手资料，记录版本和日期。区分官方支持、本地可配置、运行验证通过、指定版本可复现。未执行不写通过，不为调研自动发起付费测试。
4. 按模板填写代码树、模块、接口、状态与异常、使用、测试及发布。代码树标记新增／修改／复用，说明不改动范围；拟新增文件和接口不得描述为已存在。多仓库分别列明安装环境和交付职责。
5. 数据相关项目写来源、国内获取（优先核验 ModelScope 等可用渠道）、离线方式、版本哈希、字段映射、目录发现、确定性筛选及完整性。不虚构镜像地址。
6. 验收明确指标分子分母、单位、绝对／相对误差、阈值边界、运行次数、聚合方式及错误缺失处理。区分客户端与实际推理硬件。含糊条件保留原文并列待确认，不擅自选口径；不取最佳运行冒充均值。
7. REQ 与 TC 关联；不伪造负责人、日期、版本或测试结果。专项按实际需要裁剪。关键字段与结论适度加粗，说明与限制用斜体，标题不带模板标记。必要的架构、执行和验收分支配图，图文保持一致，不放空白图占位。

## 内容源与交付

以 UTF-8 DocxXML 作为共同源。模板资产中的维护说明和作者不是新项目事实，输出时删模板说明，替换标题及修订记录。

- 飞书：读取 `references/feishu.md`，先读最新目标，局部写入后回读。保留用户修改和资源；不擅自恢复已删除章节，不重复询问已有的写入授权。
- Word：读取 `references/word.md`，使用 `scripts/export_docx.py` 生成真实 docx；不以重命名 Markdown 代替 Word。

迭代修改时同步核对代码树、配置、图示、接口和测试，避免通过追加段落累积矛盾。明确要求写入才修改外部文档。遇到实际权限阻塞说明原因并保留本地稿，不宣称写入成功。

交付前检查完整性、版本证据、字段传递、状态隔离、失败恢复及结果口径；重新打开文件或回读飞书。Word 无渲染器时如实说明只做结构校验。最终提供可点击的飞书或绝对路径 docx 链接，简述关键未确认项；两种输出核对同一内容版本，任何产物不含真实密钥。
